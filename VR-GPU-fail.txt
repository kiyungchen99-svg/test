## 根因判斷

**這不是硬體 cable/NVLink 問題**，而是：

- **第一層根因**：18 台 compute node 的 GPU driver 全數 `LoadNvidiaDriver returned non 7`，代表這次跑測時 driver 根本沒有正確載入（exit code 不是預期的 7）。可能原因：
  - 這次是新 boot（`Dumping inforom` + fresh log 目錄 `logs-20260907-003825`），開機後 driver 模組沒被自動載入或跟 kernel 版本對不上
  - driver 套件/kernel module 在 provisioning 階段沒有真的裝進所有節點
  - Secure Boot 擋掉了未簽名的 nvidia kernel module
  - 也可能是 GPU 韌體/driver package 版本跟這次跑測用的 kernel 不匹配

- **第二層、獨立事件**：COMPUTE_NODE_0 在跑 Pulsy_3 時整台失聯，這是另一個問題（可能是 driver 沒載入疊加下，某個 stress test 觸發了 kernel panic 或硬重開機），需要單獨查 COMPUTE_NODE_0 的 IPMI/BMC log（但文件顯示 BMC IP 沒配置，這點本身也要修正，否則出問題連遠端診斷都做不到）

## 建議下一步

1. 先確認這批 18 台 compute node 這次開機後 `nvidia-smi` / `lsmod | grep nvidia` 是否正常，找出為什麼全數 driver load 失敗（很可能是 provisioning/開機腳本的系統性問題，而非個別硬體）
2. 補上 COMPUTE_NODE_0 的 BMC/IPMI IP 設定，這樣下次類似情況能抓 CPLD dump 做進一步診斷
3. driver 問題排除後，NVLink「unexpected state」的巨量訊息應該會消失（因為那是 driver 沒起來的次生症狀）；如果排除 driver 問題後 NVLink 還是報異常，才需要回頭懷疑硬體/線纜
4. 針對 COMPUTE_NODE_0 失聯，建議檢查它的 serial console log 或 IPMI SEL，確認是否有 kernel panic/watchdog reset 的紀錄
